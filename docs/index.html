Your agent setup is scattered.

If your team uses AI coding agents, your “how we work” knowledge ends up all over the place.

  • 1The same skills get copied into every repo’s .claude/skills folder.
  • 2AGENTS.md mixes how this app works with how you write code in general.
  • 3A PR-review bot gets set up by hand in three tools, and the three slowly drift apart.
  • 4Nobody knows what the agents actually did last week.

So when you improve your process, you update it everywhere by hand. And when you switch tools, you start over.

Your process gets its own repo.

Your product repo versions your code. A blueprint versions how that code gets built. A home repo says which blueprint runs where.

Your factories. Each one says: run this blueprint, on these targets, in these tools.

Live, over MCP.

Agents in those tools load your blueprint live, over MCP. Fabrica never copies it into your tools or your repos. A routine gets a tiny stub that says where its instructions live, so when you merge a change, the next run picks it up. No redeploy.

Built like infrastructure.

Plan before you apply. Keep state in git. Fail closed, and say why.

Change it once

Merge a change to a skill, rule or routine, and the next run in every tool picks it up.

Rules agents can’t rewrite

Generic skills and rules live outside your product repos, where an agent can’t quietly change them.

One routine, every tool

Write “review every new pull request” once. Each runtime’s provider turns it into a Claude routine, a Cursor automation or a local hook.

Composable blueprints

Import other blueprints and skills repos, pinned to exact commits in fabrica.lock.

Every run on record

Each session lands in a SQLite database: what was asked, which routine ran, and how it went.

Strict by default

A mistyped key stops fabrica check instead of being ignored. Plan shows every change before apply makes it.

Plan. Apply. Walk away.

Fabrica is a single static binary. You also need git. Then it’s four steps.

It puts fabrica in ~/.local/bin. Prefer Go? Build it from source.

  1. Make a blueprint

    Start from the starter blueprint that comes built in: five skills, three routines and four rules, ready to change.

  2. Add a factory

    One file in your home repo: this blueprint, on every repo, in Claude Code and Cursor.

  3. Plan, then apply

    Plan never changes anything. Apply adds one MCP server to each tool, and never writes into a product repo.

  4. Add the Fabrica line

    Make it the first line of a product repo’s AGENTS.md. From then on, every agent there works your way.

Or let your agent set it up.

Paste this into your coding agent, in your project’s repo. It installs Fabrica, moves your generic skills and rules into a blueprint, and deploys a factory back onto your repo.
